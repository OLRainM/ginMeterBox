# Design: 求职与实际使用兼顾的物业管理系统

Generated on 2026-08-10
Status: DRAFT
Mode: Builder

## Problem Statement

将现有的水电费计费系统扩展为小型物业管理系统：保留可靠的计量与账单能力，增加房屋、住户、缴费和工单闭环，并通过受控的 AI 管家降低查询与处理成本。目标是可真实使用、便于演示和讲清楚，而不是追求大而全的平台。

## What Makes This Cool

AI 管家能基于已授权的物业数据回答“本月 101 应缴多少”“哪个房间欠费”“这张报修单到哪一步了”，并能生成草稿或创建待确认任务；所有写操作都必须经过权限校验、审计与人工确认。

## Premises

1. 首期服务对象是单个小区、公寓或自主管理的房源，而非多物业公司 SaaS。
2. 账单与计量是现有核心，应优先复用，不能为新增模块破坏其数据一致性。
3. 系统保持 Go 单体分层架构；模块之间通过 service 接口协作，不拆微服务、不引入消息队列。
4. AI 是受控业务入口而非直接数据库访问者：只允许调用白名单工具，写入操作需用户确认并记录审计日志。

## Approaches Considered

### A. 账单系统增强版（最小可行）

- Effort: M
- 新增房间档案、住户档案、缴费状态、公告与只读 AI 问答。
- 优点：最快形成可展示闭环；最大化复用现有账单模块；风险最低。
- 缺点：报修和收费核销仍需后续补齐。

### B. 模块化单体（推荐）

- Effort: L
- 在同一 Gin 应用、同一数据库中增加物业档案、住户/入住、账单缴费、工单公告和 AI 管家模块。
- 优点：可真实使用；数据一致性强；架构清楚，适合简历讲解；未来能按仓储接口切换 MySQL。
- 缺点：需要完成基础数据建模及权限升级。

### C. 多租户物业 SaaS（不建议当前做）

- Effort: XL
- 加入组织隔离、支付渠道、消息队列、多租户与独立租户配置。
- 优点：扩展性上限高。
- 缺点：显著偏离当前真实使用场景，投入大且会稀释账单与 AI 的完成度。

## Recommended Approach

选择 B：模块化单体。以“一个实际管理主体”为边界，先完成物业档案 → 账单与缴费 → 报修工单 → AI 管家四条主链路。现有 `handlers → services → repository` 分层可直接沿用。

## MySQL Evaluation

### Current decision

继续使用 SQLite。当前服务刻意将连接数设为 1 并启用 WAL，适合本地部署、少量管理人员和低频写入；相比 MySQL，它少一个服务端进程，备份就是数据库文件加应用导出，部署体验更适合真实小型物业使用和求职演示。

### Switch to MySQL when

- 两名以上管理员频繁同时录入、缴费或处理工单；
- 需要让多个应用实例共用同一份数据，或在云端长期运行；
- 出现跨物业/小区的数据隔离与统计需求；
- 需要细粒度数据库账号、备份恢复、读写扩展或监控能力。

### Compatibility and migration path

- 适配度：高。现有仓储接口已经隔离大部分数据访问，业务层无需因 MySQL 改写。
- 需要新增：`MySQL` 连接配置、`go-sql-driver/mysql`、版本化 SQL migration、MySQL 仓储实现与集成测试。
- 需要调整：SQLite 初始化与一次性 JSON 迁移不能复用；主键改为 `BIGINT AUTO_INCREMENT`、金额使用 `DECIMAL(12,2)`（或后续以分为单位的整数）、时间改 `DATETIME(3)`、字符集使用 `utf8mb4`、保留房号+账期唯一索引和外键事务。
- 不要现在同时支持两种运行时数据库。先保持 SQLite；出现上述触发条件时，以导出校验、导入 MySQL、双份核对、切换配置的方式一次性迁移。

## Delivery Phases

1. **物业基础数据**：小区/楼栋/房间、住户、入住关系；将现有账单房号关联到房间档案。
2. **收费闭环**：账单状态、缴费登记、收据、欠费清单和月度汇总；保留已有报表导出。
3. **服务闭环**：报修申请、工单状态、指派、处理记录、公告。
4. **AI 管家**：知识库问答、账单/欠费/工单查询工具、生成通知/回复草稿；写操作统一采用“确认后执行”。
5. **权限与可靠性**：管理员、管家、财务、住户角色；操作日志、备份恢复演练和数据导出。

## Success Criteria

- 管理员可在一个页面完成房间、住户、读表、出账、登记缴费、处理报修。
- 住户可查看自己的账单、缴费状态和报修进度。
- AI 对数据问题的回答可追溯来源；任何改数据的行为都可被确认和审计。
- SQLite 文件备份可被恢复并通过核心账单一致性检查。

## Next Steps
