# 项目文档索引

本文档集描述当前代码已经实现的水电计费系统。`memory/2026-08-10-property-management-architecture.md` 中的房屋、住户、缴费、工单和 AI 管家属于后续规划，不计入当前业务能力。

## 阅读顺序

1. [系统架构](architecture.md)：技术栈、运行结构、分层依赖、启动过程与横切能力。
2. [功能模块](modules.md)：按功能模块说明职责、依赖、输入输出、状态和核心文件。
3. [业务链路](business-flows.md)：逐条追踪用户操作到数据库或生成文件的调用链。
4. [接口与数据](api-and-data.md)：HTTP 接口索引、统一响应、数据模型、校验规则和错误语义。

## 当前系统边界

当前系统面向单一管理主体，以“房号 + 账期”为账单唯一业务键，提供：

- 管理员登录和内存会话；
- 水电账单录入、编辑、查询、删除和费用计算；
- 从历史账单延续单个或多个房间的下期账单；
- 批量补差、额外费用和删除；
- 水表读数智能匹配；
- JSON/Excel 导入导出；
- 月度 PNG 报表生成与受限下载；
- 月度总表读数维护与住户分表补差计算；
- JSON 历史数据向 SQLite 的一次性迁移。

## 关键约束

- 当前运行数据库是 SQLite，不是 README 中仍提到的 JSON 仓储。
- SQLite 限制为单连接并启用 WAL，写操作通过事务保持一致性。
- API 除登录外均要求有效会话；浏览器写请求还校验来源。
- 服务端保存账单前总会重新计算派生费用，客户端计算结果不作为可信输入。
- 同一房号在同一月份最多一条账单。
- “总表”不能参与账单延续；总表当前有独立数据表和管理页面。
- 生成文件只通过随机 basename 和受限下载接口暴露，不返回磁盘路径。

## 维护约定

功能变化时应同步更新：

- 新增或删除模块：更新 `modules.md`。
- 新增或修改路由、DTO 或响应：更新 `api-and-data.md`。
- 改变跨层调用、事务边界或状态变化：更新 `business-flows.md`。
- 改变启动、存储、安全或部署结构：更新 `architecture.md`。
